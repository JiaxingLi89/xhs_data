# 小红书研究采集：从测试到查看数据

这个项目按关键词采集小红书笔记正文和一级评论，并导出 CSV、Excel。默认关键词是“母乳喂养”。

当前 Mac 配置使用手动分批、滚动 24 小时请求额度。49 项离线测试通过；本次修改未启动真实浏览器或采集，不能据此保证平台可用性或账号安全。历史记录见 [VALIDATION.md](VALIDATION.md)。

你需要依次确认三件不同的事：

| 检查 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 单元测试、离线演示通过 | 程序在模拟条件下能处理和导出数据 | 能连接小红书 |
| `doctor` 显示 `live_ready: true` | 本机依赖和所检查的环境条件就绪 | 登录有效、平台接口可用 |
| 真实试采并核对导出内容 | 实际获取到了可核对的数据 | 已完成整个研究样本采集 |

## 1. 文件夹里都是什么

| 文件或目录 | 用途 | 你需要做什么 |
|---|---|---|
| `README.md` | 本入门指南 | 按下面步骤操作 |

| `tests/` | 离线自动测试 | 按第 3 步运行 |
| `demo_output/` | 历次模拟结果 | 仅用于练习，不作真实研究数据 |
| `data/` | 真实数据库、断点和浏览器会话 | 运行相关命令后生成；不要随意删除，会影响续采与登录 |
| `exports/` | 真实数据导出结果 | 执行 `export` 后生成，在这里找 Excel |

| `docs/运行与维护.md` | 异常恢复、定时运行、配额等细节 | 需要时查阅 |
| `VALIDATION.md` | 已验证与待验证事项 | 判断项目目前做到哪一步 |
| `__pycache__/`、`.DS_Store` | Python 缓存、macOS 文件夹记录 | 不属于采集结果，无需操作 |

浏览器会话和数据库含访问凭证，保留在本地；需要反馈问题时提供错误信息即可，不要分享会话目录。

## 2. 打开终端并进入项目

在 Mac 上打开“终端”（可用 Spotlight 搜索），粘贴下面这行并按回车。路径中的引号需要保留：

```bash
cd "/Users/jiaxing/codex project/母乳喂养/xhs data"
```

以下命令均在这个目录执行。每次输入一条，等待执行完成后再输入下一条。项目移动后，需要相应修改上面的路径。

## 3. 先跑离线测试：无需登录

```bash
python3 -m unittest discover -v
```

末尾出现 `OK` 表示离线测试通过。这里的测试不访问真实小红书账号。离线核心需要 Python 3.9 以上。

再运行演示：

```bash
python3 -m xhs_research demo
```

使用当前默认配置时，演示生成 20 条候选、5 篇模拟笔记和 250 条模拟评论。演示保留短批次模式，使用虚拟时钟，不需要真的等待请求间隔。终端最后打印“模拟数据导出：”及完整路径。

打开该路径中的 `research.xlsx`，可提前了解表格格式。结果位于 `demo_output/日期时间/exports/时间戳/`；其中 `manifest.json` 的 `synthetic_demo` 为 `true`，表示全部是模拟数据。

**看到演示表格，只说明模拟流程成功。接下来才是准备真实采集。**

## 4. 安装依赖并检查环境

默认需要已安装 Google Chrome，并在 Mac 桌面登录状态下操作。实采需要 Python 3.10 以上，推荐 3.12；脚本会查找本机已有的兼容 Python。

```bash
python3 scripts/setup_live.py
```

脚本在项目内创建或使用 `.venv` 并安装固定版本依赖，需要联网。若提示安装未完成，先处理安装错误，不要直接跳到登录。

安装后检查：

```bash
.venv/bin/python -m xhs_research doctor
```

| 输出 | 怎么理解 |
|---|---|
| `core_ready: true` | 核心命令能够启动，不等于所有离线测试通过 |
| `live_ready: true` 且 `issues: []` | 本机检查通过，可以开始真实试采 |
| `live_ready: false` | 还缺条件，按 `issues` 中的提示处理 |
| 退出码为 2 | 这次环境检查没有通过，不代表采集过且失败 |

`doctor` 不访问小红书、不打开登录页面。请以当前 doctor 结果判断依赖是否就绪；[验收记录](VALIDATION.md) 中的安装问题是历史记录。

## 5. 第一次真实试采

初次可沿用 `config.json` 中的“母乳喂养”和所有限额。若研究关键词不同，可先修改 `keywords`，保留 JSON 的双引号和逗号格式。

环境检查通过后运行：

```bash
.venv/bin/python -m xhs_research login
```

程序会打开专用浏览器。按页面提示扫码登录；短信或验证码也在浏览器中自行完成。

**登录成功后会自动开始本次采集，不需要同时再执行 `run`。** 保持终端和浏览器打开，等待命令结束、终端重新出现输入提示符。

默认每次受控请求间隔 **2–5 分钟**，登录检查也可能等待。终端每 30 秒更新一次当前步骤、剩余秒数、预计继续时间和数据库中已完成的笔记数量。这是本地进度提示，不会额外请求小红书。

没有完整登录凭证时，程序跳过无效的服务端登录检查，按现有限速打开登录页；有凭证时仍检查其有效性，扫码后也必须通过服务端确认。已有配额、冷却和暂停不会被跳过。

浏览器启动已明确开启 Chromium 沙箱。如果 Chrome 启动失败，需要检查本机兼容性，程序不会自动退回关闭沙箱的方式。

当前 Mac 配置开启持续运行：北京时间 **每天最多 700 次受控请求**（试采与正式阶段相同），额度用完后自动等待次日继续。取消每批 5 篇、30 次请求、4 小时和午夜退出限制。搜索、登录检查、正文、评论、旧数据补采及失败尝试共用额度。每篇仍最多 50 条一级评论、20 页；请求间隔仍为 120–300 秒，按平均间隔估算全天约 411 次，700 是上限而非每日目标。

需要中途停止时，在终端按 `Ctrl+C`；已经提交的数据会保留。以后继续采集使用：

```bash
.venv/bin/python -m xhs_research run
```

请保持 Mac 唤醒、终端与浏览器打开。50 篇试采审核、1500 篇总目标、候选耗尽和原有异常仍会结束运行；审核、登录或异常处理后需手动启动。程序不自动解除风控暂停，不提供开机启动或崩溃重启。重新启动不会清除请求历史、等待、冷却或暂停。

当前 `quota_mode: "daily"`、`continuous_daily: true`，`daily_requests_pilot` 和 `daily_requests_formal` 均为 700，`daily_notes_*` 为 `null`（不另设每日篇数限制）。搜索不再每天仅一次：开始时候选不足则补充搜索，队列耗尽时继续翻页；搜索仍受总请求额度、间隔和结果耗尽限制。`status` 的 `daily_requests_remaining` 表示当天剩余额度，持续模式下每批限制显示为 `null`。旧配置不含 `continuous_daily` 时默认关闭，仍遵守每批限制；滚动模式不允许开启此开关。

### 用户字段与旧数据补采

笔记新增 `author_user_id`、`author_ip_location`，评论新增 `commenter_user_id`、`commenter_ip_location`，均带 `identity_observed_at`。字段来源与 Windows 一致，缺失留空；IP 属地是接口返回的属地，并非原始 IP 地址或常住地。

首次打开旧库会在进程锁内升级至 schema 3，升级前自动保存 `data/research.pre-identity-*.sqlite3` 备份。请先结束旧版采集进程，再启动新版本。`status` 和 `export` 不触发网络补采。下次 `run` 优先补采旧笔记与已有评论的身份字段，使用独立游标、正常请求额度和每批名额；不新增旧评论，不修改原完成状态或正文。每个任务最多遍历 20 页，已观察过但接口缺失的字段不反复重试。`identity_backfill` 和导出说明记录任务状态与缺失数；补采时新增完成篇数可能为 0。

### 广告／分享初筛与人工复核

规则与 Windows 的 `promotion-rules-v1` 一致：检查合作声明、赞助赠品、优惠码、购买引导、私信购买、代理招募，保存规则和原文证据。自动标签为“疑似商业推广”“未发现推广线索”“无法判断”；品牌名或正面评价不单独作为证据，未命中不能证明是真实分享。

```bash
.venv/bin/python -m xhs_research classify
.venv/bin/python -m xhs_research review-menu
```

新正文自动初筛；`classify` 对已有正文离线初筛，不发网络请求。也可用 `review-export`（加 `--all` 导出全部）导出 CSV，只编辑 `human_review_label` 和 `human_review_note`，再用 `review-import "文件路径.csv"` 导入。允许人工标签：明确商业推广、疑似商业推广、普通经验分享、无法判断。空白标签不清除旧复核，正文变化会使原复核失效。

`export` 保留全量 CSV/Excel，并增加 `without_confirmed_promotion/` 筛选版，仅排除人工确认且对应当前正文的明确商业推广及关联评论、来源。数据库不删除任何记录。两套导出均包含身份字段、推广证据和复核信息。


## 6. 查看状态、导出并判断成功

采集结束后，先看状态：

```bash
.venv/bin/python -m xhs_research status
```

重点看 `notes` 中各状态的数量：`complete` 表示按当前规则完成的笔记，其他状态需要进一步核对；没有 `complete` 项时，不要当作已经有完整样本。`business_requests_today` 是当天请求尝试数，**不是成功数**。`auth_waiting: true` 表示等待登录；`pause` 非空表示有暂停记录。

滚动模式重点看 `rolling_requests_used`（最近 24 小时已用）、`rolling_requests_remaining`（剩余）、`rolling_outcomes`（按结果分类）和 `next_release_local`（最早一笔额度释放的本地时间）。额度逐次释放，不在午夜归零；额度释放不等于解除暂停。带 `today` 的字段是自然日统计。`reserved` 表示已预留但未记录最终结果，也计入额度。

再导出：

```bash
.venv/bin/python -m xhs_research export
```

终端会打印本次导出目录，默认在 `exports/时间戳/`。每次导出都会创建新目录；运行采集本身不会自动生成这些 Excel 文件。

| 导出文件 | 查看内容 |
|---|---|
| `research.xlsx` | Excel 中的笔记、评论、来源三个工作表 |
| `notes.csv` | 标题、正文、时间、互动数、状态 |
| `comments.csv` | 一级评论，通过 `note_id` 与笔记关联 |
| `sources.csv` | 搜索关键词和发现来源 |
| `manifest.json` | 数据行数、关键词、模拟标记等说明 |

首次成功标准：

- **笔记链路**：至少一篇真实笔记的标题、正文等能与网页核对；`manifest.json` 中 `synthetic_demo` 为 `false`。标记为 `false` 本身不能证明采到了数据。
- **评论链路**：选一篇实际有评论的笔记，确认导出包含对应评论，`note_id` 关联正确，内容能核对。零条评论不能单独证明评论采集成功或失败。
- **完整样本**：查看 `state` 是否为 `complete`；停止原因为 `comment_cap` 表示达到评论上限，`exhausted` 表示接口当前返回结束，都不代表获取了所有历史评论。

仅打开浏览器、扫码成功、程序正常退出或生成一个空 Excel，都不能算真实采集成功。

首次链路验证后，再做累计 50 篇试采和至少 10 篇人工核对。转正式阶段的操作见 [运行与维护](docs/运行与维护.md)，不需要在第一次测试时完成。

## 7. 常见问题

| 看到什么 | 意味着什么 | 下一步 |
|---|---|---|
| `No module named xhs_research` 或找不到 `config.json` | 可能不在项目目录 | 重新执行第 2 步的 `cd` |
| `.venv/bin/python` 不存在 | 虚拟环境尚未创建 | 执行安装脚本 |
| `doctor` 提示依赖未安装 | 环境不完整 | 重新执行安装脚本，保留完整错误信息 |
| 安装时报网络错误或无法获取版本列表 | 尚不能判定是版本不存在还是连接失败 | 检查终端联网情况；本地安装方式见维护文档 |
| 浏览器已打开，但没有数据 | 可能尚未确认登录，或正在限速等待 | 查看终端提示，完成扫码并等待；登录最多等待 10 分钟 |
| `auth_waiting: true` | 上次登录等待未完成 | 准备好扫码后执行 `login` |
| 本批笔记或请求额度用完 | 本批结束 | 查看状态、导出核对后，自行决定是否再执行 `run` |
| 最近24小时请求额度用完 | 跨批累计达到上限 | 查看下一笔额度释放时间，不删除历史 |
| 提示网络或浏览器连接中断 | 已保存进度并退避 | 检查网络，至少等待 15 分钟后再尝试；若已暂停则先查暂停原因 |
| 验证、限流、风控暂停 | 程序已停止继续请求 | 检查账号和暂停原因，冷却结束后按维护文档使用 `resume`；重新登录不会清除暂停 |
| `protocol_error` | 接口响应与预期不一致 | 停止试采并检查适配器，不能把异常当作零条结果 |
| 导出为空或只有候选 | 尚未获得可用正文、评论 | 查看 `status`、终端信息和导出状态，确认运行的是实采而非演示 |

## 进阶说明

[运行与维护](docs/运行与维护.md) 包含完整的限额、恢复规则、自定义配置、定时运行和导出字段口径；[上游说明](third_party/README.md) 记录来源与许可证。

滚动模式只允许手动开启批次，拒绝创建定时任务；已有定时任务触发时会退出，不执行采集。旧 daily 模式保留原有定时功能。

### 浏览器受限诊断

遇到 `browser_page_restricted` 时，程序会在配置的采集数据目录（`research.sqlite3` 所在目录）追加 `browser-diagnostics.jsonl`，并在终端显示脱敏记录。记录包含 UTC 时间、状态码、白名单域名和接口路径、资源类型及观察到响应时的程序阶段；未知路径和动态标识会隐藏，不记录查询参数、请求头、Cookie 或正文。阶段仅表示当时程序状态，不证明请求由该阶段发起。

下次自然出现异常后，可提供该诊断文件或终端中的“浏览器受限诊断”行用于排查；不要提供浏览器配置目录或完整数据库。此修改不改变暂停、冷却或登录确认规则，也不能补回此前未记录的触发请求。
