# 运行与维护

返回 [入门指南](../README.md)。首次测试请先按入门指南操作。

## 登录与异常恢复

| 状态 | 行为 |
|---|---|
| 有效登录态、程序重启 | 复用`data/browser-profile`，从数据库断点继续 |
| 浏览器已更新Cookie | 每次请求从浏览器读取，不长期缓存旧Cookie |
| 登录失效 | 本地检查凭证，缺少完整凭证时跳过无效检查；已有凭证仍由服务端验证，仍失效则每日最多自动打开一次登录页 |
| 等待扫码 | 最多等待10分钟；成功后验证服务端登录状态再续采 |
| 登录等待超时 | 持久化为`auth_waiting`，后续定时任务不反复弹窗；使用`login`主动处理 |
| 断网、超时、5xx | 不触发登录；保存至少15分钟退避，后续run或下个计划时段再尝试 |
| 浏览器断开 | 单次运行最多重建一次；原请求的退避、配额仍然有效 |
| 同一请求连续两次网络失败 | 持久化暂停，需要检查后`resume`；不无限循环 |
| 验证、403、限流、安全限制 | 全局暂停，重新登录不清除暂停 |
| 笔记删除 | 标记`unavailable`，不重试；已尝试笔记计入本批名额；daily 模式也计入当天上限 |
| 链接凭证失效 | 标记`needs_link`，下一次有搜索额度时回原搜索来源刷新一次；找不到则留待核对 |
| 响应结构变化、异常空正文 | 标记`protocol_error`并暂停，不伪装成零条数据 |

429优先使用`Retry-After`，缺失时冷却24小时。页面自身观察到的限制响应保守冷却24小时。冷却到期不会自动解除风控暂停：检查后执行`resume`，再手动运行`run`。登录等待用`login`处理。

```bash
.venv/bin/python -m xhs_research resume
.venv/bin/python -m xhs_research run
```

会话目录和SQLite包含访问凭证，只保存在本地受限目录；不提交到Git，不写入日志或导出。日志只记录受控诊断代码。收到验证码时仍需要人工处理；保存登录状态不保证服务端永久认可会话。

## 采集预算和试采验收

当前 Mac 配置为 `quota_mode: "daily"`、`continuous_daily: true`，北京时间自然日总请求 700 次，试采、正式阶段一致。每天可多次搜索，搜索、正文、评论、登录检查、旧字段补采与失败尝试共用总额度。

| 项目 | 试采和正式阶段 |
|---|---:|
| 每批不同笔记，含续采、补采和失败尝试 | 不另设限 |
| 每批受控请求 | 不另设限 |
| 每自然日受控请求 | 700 |
| 请求间隔 | 120–300 秒 |
| 每篇一级评论上限／页数上限 | 50 条／20 页 |

`daily_notes_*: null` 不另设每日篇数限制。`daily_requests_*` 控制每天总请求。持续模式忽略 `requests_per_run`、`notes_per_run` 和 `run_timeout_seconds`，跨午夜继续；每日额度用完后每30秒更新本地等待提示，次日自动继续并遵守已保存的请求间隔。切换阶段或重启不清除当天请求历史。缺省或关闭 `continuous_daily` 时保留原有批次限制；此开关仅支持 daily 模式。

请保持 Mac 唤醒、终端与浏览器打开；没有新增开机启动或崩溃重启服务。按平均210秒间隔估算全天约411次，700只是额度上限。试采审核、总目标、结果耗尽和现有异常停止条件保留；额度释放不会解除暂停。

用户 ID、IP 属地补采和推广初筛／人工复核命令见 README 对应说明。首次旧库升级自动备份；旧数据补采独立续接，仅更新已有评论字段，不扩大原有样本。导出新增全量与人工确认推广筛选版。

以先达到的上限为准。请求在发送前预留配额：即使预留后程序崩溃或签名失败也不退回，以防重启造成超额。因此`business_requests_today`是保守计数，不是成功请求数。`page_requests_today`单独记录可观察的浏览器页面流量，不包含启动监听前的流量，不能将业务额度等同于全部网络请求。

搜索结果先入队，正文与评论串行处理；候选不足20篇时才补充。所有关键词共享预算。最后一页即使`has_more=false`仍会保存其中结果。评论每页与游标在同一事务提交，重复游标会停止并标记不完整。二级回复和媒体下载关闭。

暂停、游标、请求历史和下次请求时间都存入 SQLite。滚动窗口统计请求时间大于“当前时间减 86400 秒”的全部记录，满 24 小时逐次释放；重启、恢复和升级保留历史。窗口检查与请求预留在同一事务内，并为请求时间增加索引。自然日统计按 Asia/Shanghai 划分；滚动模式每次最长 4 小时且可跨午夜，旧 daily 模式仍在跨日时结束。签名在等待结束后生成，网络库内部重试和自动跳转关闭。

status 显示滚动已用/剩余额度、最近 24 小时各类结果计数及下一笔释放时间；每批报告处理数、新增完成数、请求数、累计完成数和停止原因。释放时间不是账号冷却结束时间。

试采达到50篇后停止，人工核对至少10篇的正文、时间、互动数、评论归属和字段质量，再执行：

```bash
.venv/bin/python -m xhs_research promote --reviewed-notes 10
```

这是对实际人工核对的记录，程序不会代替内容审核。正式阶段默认目标1500篇完整笔记，允许配置调整；不会自动提高频率。关键词无新结果时可能达不到目标，应根据研究方案更新关键词并保留采样版本。

## 定时运行

rolling 模式仅手动启动：拒绝生成定时任务，已有任务以 `--scheduled` 触发也会在打开浏览器前退出。不自动卸载已有 launchd 配置。以下操作适用于 daily 模式。持续模式直接运行一次即可跨日继续；已有定时任务仍受进程锁约束，不会同时启动多个采集进程。

先完成安装和首次登录，再生成并安装用户级launchd任务：

```bash
.venv/bin/python -m xhs_research schedule
.venv/bin/python -m xhs_research schedule --install
```

默认北京时间10:00、16:00；要求系统时区和配置一致。计划文件和日志保存在项目`schedule/`中，不复制到系统目录。没有使用`--install`时只生成文件，不激活任务。`--install`会检查依赖；本次实现环境中未激活。

唤醒后若已错过时段15分钟则跳过，已运行时段不重复执行。单进程锁防止手工任务与定时任务同时操作同一浏览器。关机、未登录桌面会话或休眠期间不采集，不承诺全天无人值守。

卸载时使用生成文件中的实际Label（也可从文件名去掉`.plist`获得）：

```bash
launchctl bootout "gui/$(id -u)/local.xhs-research.实际后缀"
```

## 输出和研究口径

每次导出生成带时间戳的新目录，包括：

- `notes.csv`：正文、标题、发布时间、互动数、采集状态和停止原因。
- `comments.csv`：仅一级评论，使用note_id关联笔记。
- `sources.csv`：关键词、排序、页码、页内位置、搜索会话、发现时间与采样版本。
- `research.xlsx`：同样内容的三个工作表。
- `manifest.json`：行数、配置摘要、时间口径、模拟标记及采样限制。

昵称、头像、主页信息、Cookie、链接凭证均不导出。笔记ID和评论ID用于去重与关联，因此导出数据不应被当成完全匿名数据。笔记和评论的发布时间保留平台原值；采集时间为Unix秒。互动数保留平台字符串，避免把“1.2万”等值伪装成精确整数。

CSV为带BOM的UTF-8，可用Excel打开；公式前缀会转义。XLSX使用文本单元格，单元格最多32767字符，完整长文本以CSV为准。`state != complete`的笔记是未完成或需要核对的样本。`comment_cap`表示截断，`exhausted`表示平台当前返回已结束，不代表所有历史评论。

默认综合排序和前50条评论属于平台返回顺序下的方便样本，不是随机抽样；来源信息保留用于研究方法说明。

## 实现与维护

核心仅依赖Python标准库。`adapter.py`使用Playwright共享Cookie存储；`mediacrawler_protocol.py`保留精简的MediaCrawler只读请求结构，`control.py`统一控制配额和登录，`engine.py`处理分页，`store.py`保证持久化。未引入完整上游项目的批量循环或自动重试。

上游来源和许可证见[上游来源与许可证](../third_party/README.md)。实采依赖固定版本，`upstream.lock.json`校验本地适配快照。接口变化时应审阅修改、重新运行测试和小样本试采，再更新快照，不能盲目刷新锁文件。

如网页接口持续不可用，可替换适配器为正常网页浏览采集；任务队列和限速层可复用。目前仅实现接口适配器，不把尚未编写的页面采集后备路线声称为可用功能。


## 环境与配置补充

实采需要 Python 3.10 以上，推荐 3.12。安装脚本优先使用当前兼容的 Python，版本过旧时查找本机已有 Python 或 Miniconda，只创建项目内 `.venv`。安装成功后生成 `requirements-resolved.txt`，记录完整已解析依赖。离线安装可执行 `python3 scripts/setup_live.py --wheels /本地wheel目录`。

默认使用 Google Chrome。若将 `browser_channel` 改为 `chromium`，还需执行 `.venv/bin/python -m playwright install chromium`。

自定义配置参数必须放在子命令前，例如：

```bash
.venv/bin/python -m xhs_research --config "/绝对路径/config.json" run
```

配置中的数据路径相对于配置文件目录。关键词和排序变化会产生新的采样版本，已入队任务继续保留。独立研究可使用新的 `data_dir` 和 `export_dir`，例如 `data/研究二` 和 `exports/研究二`，保持在已忽略的目录内。

## 登录体验与浏览器沙箱更新

浏览器启动显式使用 `chromium_sandbox=True`，不自动降级关闭沙箱。缺少 `web_session` 或 `a1` 时跳过前置服务端登录检查；凭证存在并不视为登录成功，仍需服务端验证。登录页导航与扫码后的确认继续经过统一限速和配额控制。

等待消息每 30 秒使用本地时钟更新，注明当前步骤、剩余时间、预计继续时间和数据库中完成的笔记数，不额外请求平台。完成数量包括历史数据，不是本轮新增数；模拟运行中的数量也仍属于模拟数据。

已审阅本次浏览器启动与本地凭证检查改动，并更新适配器快照哈希。离线测试通过不代表真实 Chrome 启动或平台接口已验证，也不构成降低平台风控概率的保证。

### 响应异常诊断

出现“响应结构异常”时，终端会显示具体错误子类型以及失败阶段（`signing`、`response`、`request` 或 `validation`）。`status` 中的 `last_protocol_error` 保存最近一次诊断及时间；旧版本产生的异常无法补回这些细节。HTTP 状态、数字平台错误码、字段类型仅在可取得时记录，不记录完整响应、平台消息、Cookie 或签名。请求层诊断还包含请求类型及本地请求记录 ID。

同一暂停原因重复向上传递时只记一次暂停事件；解除后再次失败会产生新事件。字段验证失败仍可能对应请求历史中的 `ok`（表示请求层成功），以 `last_protocol_error` 的 `validation` 阶段判断校验失败。

修复诊断并不等于已修复平台返回异常。先人工确认浏览器账号可正常浏览、没有验证码或访问受限提示，再执行 `.venv/bin/python -m xhs_research resume` 和 `.venv/bin/python -m xhs_research run`。程序从已保存的评论游标继续；若再次异常，保留暂停并依据具体诊断处理，不连续重试或清库。
